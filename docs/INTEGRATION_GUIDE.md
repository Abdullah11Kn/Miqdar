## 2. How This Connects to Your Other Workspace (`senior project api test`)

Your other workspace (`senior project api test`) contains image dataset evaluations (`food_ai.py`, `compare_models.py`, `evaluation_sheet.csv`, `evaluation_400_dataset.csv`, etc.). Here is how the two components integrate:

### A. Vision Recognition Layer (`recognition.py` ↔ `food_ai.py`)
1. **Separation of Concerns**: In Miqdar, AI vision models are **only** used to classify candidate food labels (with confidence scores). They **never** fabricate nutrition data.
2. **Connecting Custom Models**:
   - `miqdar_backend/recognition.py` includes a `RemoteRecognitionProvider` and `GeminiRecognitionProvider`.
   - If you want the Miqdar backend to use your models tested in `food_ai.py`, you can either:
     - Set `MIQDAR_RECOGNITION_PROVIDER=remote` and point `MIQDAR_CLOUD_ENDPOINT` to your model server.
     - Or import your classifier functions from `food_ai.py` into `recognition.py` as an additional provider subclass (`class CustomModelProvider(RecognitionProvider)`).

### B. Predefined Database Mapping
- Once candidate labels are generated by the vision model (e.g., `"medjool dates"`, `"banana"`, `"chicken breast"`), `miqdar_backend/database.py` maps the label against `database/miqdar_nutrition.db` and alias tables.
- It then calculates exact nutrition values scaled by the physical scale's weight in grams.

### C. Scale Weight & Sequential Detection
- `detect_new_food(...)` in `recognition.py` evaluates whether:
  1. Scale weight increased by $\ge 5$g.
  2. The camera image frame visually changed (using perceptual hashing and RGB difference).
- Only when both conditions are satisfied does the system perform recognition, preventing redundant API calls.

### D. Flutter App Integration
- The Flutter application connects to the backend REST API:
  - `GET /health`: Health and active provider status.
  - `POST /api/v1/recognize`: Receives image + weight, returns mapped food item, nutrients, and alert status.
  - `GET /api/v1/recommendations`: Recommends meals based on past meal variety and user health profile.
  - `POST /api/v1/profile`: Persists health conditions and dietary goals.

## 3. Step-by-Step Merge & Combination Instructions

To merge this bundle into your primary project directory:

### Step 1: Extract the Archive
Unzip `Miqdar_Full_Stack_Bundle.zip` into your chosen project root.

### Step 2: Combine Python Requirements
If you have an existing `requirements.txt` (from `senior project api test`):
```bash
# Append backend requirements if not already present
cat backend/requirements.txt >> requirements.txt
python3 -m pip install -r requirements.txt
```

### Step 3: Configure Environment Variables
Copy and customize the environment file:
```bash
cp backend/.env.example backend/.env
```
Edit `backend/.env`:
```ini
MIQDAR_HOST=0.0.0.0
MIQDAR_PORT=8080
MIQDAR_RECOGNITION_PROVIDER=mock   # Use 'gemini' when GEMINI_API_KEY is provided
GEMINI_API_KEY=your_key_here
GEMINI_MODEL=gemini-3.1-flash-lite
```

### Step 4: Build / Verify the Nutrition Database
```bash
python3 database/scripts/build_database.py --replace
```

### Step 5: Run Acceptance Checks
Verify both backend and Flutter applications pass all tests:
```bash
./run_checks.sh
```

### Step 6: Launch Backend & Mobile App
1. **Start the API Server**:
   ```bash
   ./start_server.sh
   ```
2. **Start the Flutter App** (in a separate terminal):
   ```bash
   cd mobile
   flutter run
   ```

## 4. Key Endpoints Reference

| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/health` | Server status and active recognition provider |
| `POST` | `/api/v1/recognize` | Multipart image + weight recognition and nutrient scaling |
| `GET` | `/api/v1/foods` | List and search predefined foods |
| `GET` | `/api/v1/recommendations` | Explainable meal suggestions with rationale |
| `POST` | `/api/v1/profile` | Update user dietary profile & conditions |
| `GET` | `/api/v1/history/summary` | Query 90-day history aggregations |
